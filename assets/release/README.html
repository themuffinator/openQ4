openQ4

Release package for the open-source Quake 4 engine and game-code replacement.

This package contains openQ4 binaries plus the staged baseoq4/ runtime payload and the q4xbase/ game modules for Quake 4: The Awakening. Quake 4 assets and the expansion's content are not included.

Open Documentation Portal Project Overview Technical Reference

Requirements

Minimum client: 64-bit CPU matching the package architecture, 4 GB RAM, a working OpenGL compatibility driver with ARB2-era vertex/fragment program support, and about 12 GB free for openQ4 plus the retail Quake 4 assets.

Recommended client: modern quad-core CPU, 8 GB RAM, OpenGL 4.1+ compatibility-class GPU with 2 GB+ VRAM, current graphics drivers, and 15 GB+ free. Use 16 GB RAM and 6 GB+ VRAM for high resolutions, quality, or ultra presets.

  • A legitimate Quake 4 installation from Steam or GOG.
  • The stock retail PK4 files in a q4base/ directory, available through openQ4's asset discovery or a manual fs_basepath setting.
  • A supported package target: Windows x64, Linux x64, or Steam Deck/SteamOS; preview Linux ARM64 or preview Apple Silicon/arm64 macOS; or experimental Windows ARM64.
  • Use the minimum, lowpower, low or performance presets on constrained systems before enabling expensive visual options.

Getting Started

  1. Install Quake 4 from Steam or GOG and leave its retail q4base/ folder intact.
  2. Install or extract openQ4 to its own folder when possible. On Windows, either run the installer executable or extract the archive; the installer can detect an existing openQ4 install, adds a standard uninstall entry, and optionally registers openq4:// browser links. On Linux, you can instead run the matching AppImage directly after chmod +x openq4-*.AppImage.
  3. Use a clean layout: preferably keep retail Quake 4 separate with assets under q4base/; for a portable setup, keep a copied retail q4base/ beside openQ4's baseoq4/. Never copy retail PK4s into baseoq4/.
  4. Run openQ4-client_<arch>, openQ4-client_<arch>.exe, or the Linux AppImage. The AppImage bundles openQ4 runtime libraries but still discovers the separately installed retail Quake 4 assets; it never embeds them.
  5. On Steam Deck, use openQ4-steamdeck when it is included in the package. Direct openQ4-client_<arch> launches on Steam Deck or SteamOS also auto-select the Deck profile when com_platformProfile is still default.
  6. Open docs/index.html for the full offline documentation set, or use the installer-created Start Menu shortcuts on Windows.
  7. If auto-detection fails, launch with +set fs_basepath "path\\to\\Quake 4", pointing at the retail root that contains q4base/.

Windows ARM64 Experimental Notes

  • Windows ARM64 packages are experimental. They are built natively for Arm64 and automated tests start the dedicated server, but nothing has started the game client automatically yet, and no real-hardware report has confirmed that the packages run.
  • openQ4 renders with OpenGL by default. If the renderer does not start on a Windows on Arm device, launch with +set r_renderApi vulkan.
  • Please report what happens, including runs that simply work, with the Windows ARM64 issue template on the openQ4 issue tracker.

Linux ARM64 Preview Notes

  • Linux ARM64 packages remain preview builds until physical ARM64 hardware completes native-Wayland SP/MP gameplay, dedicated-server, audio, input, and package signoff.
  • The package requires 64-bit little-endian AArch64 hardware, an Ubuntu 24.04-class desktop userspace, and a desktop OpenGL compatibility driver with Wayland/EGL or X11/GLX support.
  • GLES-only boards are not covered by the current Linux ARM64 package.

Steam Deck Notes

  • The Deck launcher enables the steamdeck platform profile and sets OPENQ4_STEAMDECK=1.
  • Native Wayland is the default SDL path when available. Set OPENQ4_FORCE_X11=1 to force the XWayland fallback from the Deck launcher or a direct client launch.
  • If native Wayland hits a compositor/libdecor startup or decoration issue, set OPENQ4_WAYLAND_DISABLE_LIBDECOR=1 for that launch.
  • Deck controller tuning lives under Settings -> Game Options -> Controller, including gyro, touchpad mode, touchscreen routing, and low-battery rumble caps.
  • Run listControllers from the console when reporting Deck input, battery, gyro, touchpad, or touchscreen issues.

macOS Preview Notes

  • macOS support is a preview. Current packages are for Apple Silicon/arm64 Macs on macOS 11 or later. Players have run them on macOS 26, including the single-player campaign and multiplayer with sound, but nothing older than the current macOS has been tested. Intel Mac and universal2 packages are not published yet, and Rosetta is not a supported release target.
  • Release runs with Apple Developer ID signing and notarization credentials publish signed/notarized OpenGL and Metal bridge DMGs. Those credentials are not set up yet, so current releases publish clearly labeled -unsigned.tar.gz archives instead.
  • Unsigned macOS archives are ad-hoc signed only for bundle validity, are not notarized, and may require normal Gatekeeper approval on first launch.
  • The Metal package is a bridge mode around the existing OpenGL renderer, preserving stock-asset compatibility while Metal translation-layer work continues; it is not a native Metal renderer.
  • Both macOS packages also carry openQ4's experimental Vulkan renderer. Apple ships no Vulkan driver, so on macOS it runs on top of MoltenVK, a Vulkan-on-Metal translation layer bundled inside the package. It is a translation layer, not a Metal renderer.
  • macOS packages bundle OpenAL Soft for audio; no Homebrew or separate audio install is required. Its LGPL notice and corresponding source archive are included inside openQ4.app/Contents/Resources/licenses/openal-soft/.
  • OpenGL remains the default and recommended macOS renderer in both packages. Vulkan is opt-in: run r_renderApi vulkan in the console, then quit and relaunch openQ4. It is a runtime option rather than a separate download, so there is no third macOS package to install.
  • Expect problems if you try it. The Vulkan renderer is experimental on every platform, and on macOS only one player has reported it working. If it cannot start, openQ4 logs the reason and renders with OpenGL instead; if it only fails later, while creating the window, openQ4 stops with an error and the next launch uses OpenGL. Run r_renderApi gl and restart to go back.
  • Open the DMG or unpack the -unsigned.tar.gz archive, drag openQ4.app to /Applications (or another user-writable folder), then launch it. The app contains openQ4's runtime data and signed SP/MP modules. Keep the whole package only for the loose diagnostic client, dedicated server, or support collector; do not add retail q4base assets to the signed app.
  • For macOS crashes, attach full terminal output as text plus openq4.log and any matching .ips report. Run collect_macos_support_info.sh from the package root to collect Rosetta, renderer, architecture, dependency, signing, and quarantine diagnostics, then see the macOS support-data guide.

Package Contents

  • openQ4-client_<arch> and openQ4-ded_<arch>: engine binaries.
  • *.pdb files on Windows: diagnostic symbols that make crash dumps actionable.
  • baseoq4/pak0.pk4 (inside openQ4.app/Contents/Resources on macOS): openQ4-owned runtime content and overrides.
  • Single Player → Campaign: choose Quake 4 or The Awakening when expansion content is installed. Both use the bundled baseoq4 SP module, with separate saves and content mounts. Supply the unfinished alpha content separately; see the campaign guide.
  • docs/index.html: full packaged HTML documentation portal.
  • docs/docs/user/ and docs/docs/dev/: converted user and developer references.
  • VERSION.txt: packaged version metadata.
  • LICENSING.md: component terms and distribution considerations. LICENSE and the accompanying Additional Terms cover the engine; LICENSES/QUAKE-4-SDK-EULA.rtf covers SDK-derived game code.

Crash Reports

On Windows, unhandled openQ4 crashes write a crash log and memory dump under crashes/ beside the executable. Attach both generated files when reporting a crash.

Documentation

The release archive includes a full offline HTML docs site instead of only a single readme. Start with docs/index.html, then move into the overview, build guide, technical reference, user guides, and developer notes.
