openQ4

The modern way to play Quake 4. openQ4 is an open-source engine and game-code replacement that runs the original retail game on today's PCs, handhelds and Macs.

This package holds everything openQ4 needs to run: the game, the dedicated server, openQ4's own data in baseoq4/ and the offline documentation. Quake 4 assets are not included, and neither is the content of the Quake 4: The Awakening expansion. You need your own copy of Quake 4 from Steam or GOG.

Quick Start

  1. Install Quake 4 from Steam or GOG and leave its q4base/ folder as it is.
  2. Put openQ4 in its own folder, separate from Quake 4:
    • Windows: run the installer, or extract the ZIP.
    • Linux: extract the archive, or use the AppImage, a single-file app that needs no installing. Run chmod +x openq4-*.AppImage once to make it executable, then start it.
    • macOS: drag openQ4.app to your Applications folder. See the macOS notes below.
  3. Start the game: openQ4-client_<arch>.exe or the Start menu shortcut on Windows, openQ4-client_<arch> or the AppImage on Linux, and openQ4-steamdeck on Steam Deck.
  4. openQ4 finds your Quake 4 installation by itself. If it doesn't, start it with +set fs_basepath "path/to/Quake 4", naming the folder that contains q4base/, not q4base/ itself.
  5. On first launch openQ4 picks a performance preset for your hardware. To change it, open Settings → Display (System in the classic menus) and choose another Performance Preset, or press Auto-Detect to pick again.

Upgrading from an older openQ4? Install the complete package rather than replacing individual files. If you use an archive, extract it into a fresh folder, and delete any baseoq4/ folder left by an older openQ4 rather than mixing old and new files. Your settings, key bindings and saves carry over, but older versions of openQ4 can't read saves made by newer ones, so back up your saves if you might go back. Release status has the details.

Portable setup: to keep everything in one place, put a copy of Quake 4's q4base/ folder next to openQ4's baseoq4/. Never copy Quake 4's .pk4 files into baseoq4/.

Requirements

  • Your own copy of Quake 4 from Steam or GOG, with its original q4base/ files. openQ4 finds Steam and GOG installations automatically.
  • Minimum: a 64-bit dual-core CPU that matches this package (x64 or arm64), 4 GB of memory, working OpenGL graphics drivers with about 1 GB of video memory, and about 12 GB of free space including Quake 4.
  • Recommended: a modern quad-core CPU, 8 GB of memory (16 GB for the higher presets and resolutions), OpenGL 4.1 or Vulkan graphics with 2 GB or more of video memory (6 GB or more for the Quality preset and above), current graphics drivers, and 15 GB or more of free space.
  • Windows 10 or 11 is recommended. The Linux builds need a modern 64-bit desktop comparable to Ubuntu 24.04 or newer.
  • On older or low-power hardware, start with the Minimum, Low Power, Low or Performance preset before turning on expensive options.

Packages: the main builds are Windows x64 (installer or ZIP), Linux x64 (AppImage or archive) and Steam Deck (the Linux archive). The others are less tested: preview Linux ARM64, preview Apple Silicon/arm64 macOS, and experimental Windows ARM64 and Android. Signed macOS builds for Apple Silicon and Intel Macs are offered separately by Mac Source Ports.

Graphics Renderer

  • A new installation starts on Automatic: openQ4 tries Vulkan first and uses OpenGL if Vulkan can't start, noting the reason in its log. A renderer you chose in an older openQ4 stays chosen.
  • Vulkan is supported on Windows and experimental on Linux and macOS.
  • To choose a renderer yourself, pick it under Settings → Display → Rendering Backend and follow the restart prompt, or start openQ4 with +set r_renderApi gl for OpenGL or +set r_renderApi vulkan for Vulkan. If the game won't start or draws incorrectly, try the other one.

Windows Notes

  • The installer adds Start menu shortcuts for the game, the dedicated server, the documentation and this page, plus a standard uninstall entry. It notices an existing openQ4 installation, and it can register openq4:// links so that a server link in your browser opens openQ4 and joins that server.
  • The installer downloads the light-grid and loadscreen packs during setup when your openQ4 folder doesn't already have them, so stay online while it runs. The ZIP already contains them.
  • Debugging symbols (.pdb files) are not in this package. They are only needed to analyse crashes, and are published separately as openq4-<version>-windows-<arch>-symbols.zip.

Windows ARM64 Experimental Notes

  • Windows ARM64 packages are experimental. They are built natively for Arm and automated tests start the dedicated server, but nothing has started the game client automatically yet, and no one has yet reported running them on real hardware.
  • If the game doesn't start or draws incorrectly on a Windows on Arm device, try each renderer in turn: launch with +set r_renderApi gl, then with +set r_renderApi vulkan.
  • Please tell us what happens, even if it simply works, with the Windows ARM64 issue template on the openQ4 issue tracker.

Linux ARM64 Preview Notes

  • Linux ARM64 packages are preview builds: they have not yet been fully tested on real ARM64 hardware.
  • They need a 64-bit ARM (AArch64) computer running a desktop Linux comparable to Ubuntu 24.04, with full desktop OpenGL drivers, on either a Wayland or an X11 desktop.
  • Boards whose graphics drivers offer only OpenGL ES can't run this package.

Steam Deck Notes

  • Start openQ4-steamdeck from the Linux archive. It switches on openQ4's Steam Deck profile and sets OPENQ4_STEAMDECK=1. Direct openQ4-client_<arch> launches on Steam Deck or SteamOS also auto-select the Deck profile, unless you have changed com_platformProfile yourself.
  • openQ4 uses the Deck's native Wayland display when it can. If the window misbehaves, set OPENQ4_FORCE_X11=1 for that launch to use the older X11 (XWayland) path instead. If only start-up or the window's title bar has trouble, try OPENQ4_WAYLAND_DISABLE_LIBDECOR=1.
  • Tune gyro aiming, touchpad mode, the touchscreen and the low-battery rumble limit under Settings -> Game Options -> Controller.
  • When you report a controller, battery, gyro, touchpad or touchscreen problem, run listControllers in the console and include what it prints.

macOS Preview Notes

  • macOS support is a preview. Current packages are for Apple Silicon/arm64 Macs on macOS 11 or later. Players have run them on macOS 26, including the single-player campaign and multiplayer with sound, but nothing older than the current macOS has been tested. Intel Mac and universal2 packages are not published yet, and Rosetta is not a supported release target. For a signed build that also runs on Intel Macs, see Mac Source Ports.
  • When Apple signing is available, releases publish signed/notarized OpenGL and Metal bridge DMGs. It is not set up yet, so current releases publish clearly labeled -unsigned.tar.gz archives instead. These are ad-hoc signed only for bundle validity and are not notarized, so macOS asks you to approve the app the first time you open it.
  • Open the DMG or unpack the -unsigned.tar.gz archive, drag openQ4.app to /Applications (or another folder you can write to), then open it. The app contains openQ4's runtime data and signed SP/MP modules (the single-player and multiplayer game code), so it is all you need to play. Keep the rest of the package only if you want the separate diagnostic client, dedicated server or support collector, and don't add Quake 4's q4base files to the app.
  • The OpenGL and Metal bridge packages both draw with openQ4's OpenGL renderer. The Metal bridge package is groundwork for future Metal support, not a native Metal renderer.
  • Both packages also include the experimental Vulkan renderer. Apple ships no Vulkan driver, so it runs through MoltenVK, a layer bundled with the app that translates Vulkan to Apple's Metal graphics. New installations start on Automatic, which tries Vulkan and uses OpenGL if it can't start. Only one player has reported Vulkan working on a Mac, so expect problems. To stay on OpenGL, choose OpenGL under Settings → Display → Rendering Backend, or run r_renderApi gl in the console and restart openQ4.
  • Sound works out of the box: the packages bundle OpenAL Soft, so no Homebrew or separate audio install is required. Its licence notice and source archive are in openQ4.app/Contents/Resources/licenses/openal-soft/.

Package Contents

  • openQ4-client_<arch> is the game and openQ4-ded_<arch> the dedicated server for hosting multiplayer games. On Windows both end in .exe; on macOS you play from openQ4.app.
  • openQ4-steamdeck (Linux archives) is the Steam Deck launcher.
  • baseoq4/ (inside openQ4.app/Contents/Resources on macOS) holds openQ4's game code and its own data, in three packs: pak0.pk4 for the menus, fonts, text and shaders, pak1.pk4 for the baked light grids and pak2.pk4 for the loadscreens. Later patch releases may also offer a small update archive without pak1.pk4 and pak2.pk4; their release notes say when you can use it.
  • The Awakening needs nothing extra from this package: the expansion runs on the same game code as Quake 4. Put the expansion's q4xbase folder, which you supply yourself, next to Quake 4's q4base folder, then choose it under Single Player → Campaign. See the campaign guide.
  • docs/index.html opens the offline documentation.
  • VERSION.txt records the version, platform and architecture of this package.
  • LICENSE, LICENSING.md and the licenses/ folder set out the terms for each part of openQ4. The engine is under the GNU GPL (LICENSE and its accompanying Additional Terms); the game code comes from the Quake 4 SDK and is covered by licenses/QUAKE-4-SDK-EULA.rtf. CONTRIBUTORS.md lists the people behind openQ4.
  • collect_macos_support_info.sh (macOS packages) gathers diagnostics for bug reports.

Crash Reports and Help

  • Windows: if openQ4 crashes, it writes a crash log and a memory dump to the crashes/ folder beside the executable. Attach both files to your report.
  • macOS: run collect_macos_support_info.sh from the package root, then attach the archive it creates, the full terminal output as text, openq4.log and any matching .ips crash report. The macOS support-data guide explains each step.
  • Report problems on the openQ4 issue tracker with your log file and setup details, or ask in #openq4 on the DarkMatter Discord.

Documentation

The full documentation is included for offline reading. Start at docs/index.html for installation, settings, campaigns, multiplayer, Steam Deck, macOS and every other player guide, plus the build guide and technical reference for developers. On Windows, the installer also adds a Documentation Portal shortcut to the Start menu.
