# Editable UI documents and presentation timelines

8 September 2026. This is the first implemented canonical-source checkpoint on
`idtech5-ui`. It establishes typed layout/text/tokens and presentation tracks,
with a source-preserving editing API shared by the future editor and runtime.
It is **not** the complete paint/component/state/binding schema, editor, input
bridge or translated GUI corpus. Those remain required by the
[delivery plan](../plans/idtech5-ui.md) and
[visual specification](../ui-visual-design.md).

## Source and compatibility

Author `.q4ui` files as UTF-8 JSON with `//` and `/* ... */` comments. A file
identifies itself with `"format":"openq4-ui"`, `"version":1` and a stable `id`.
The file is the source of truth. RML generated by `Document::BuildMarkup` is a
derived layout product, never a competing editable/save format.
An optional UTF-8 BOM and LF/CRLF line endings are preserved through value edits.

Version 1 is under development on this branch. Future required node families
must acquire concrete schemas and runtime behavior before migration can use
them. Unknown versions, core fields, properties and node types are errors.
They are never silently omitted from rendering. Opaque data is allowed in an
explicit `extensions` object, including within typed values, nodes, timelines,
tracks and keys. Root `editor` is an opaque object for editor metadata.
Extensions cannot inject markup or executable behavior.

IDs contain 1–128 ASCII letters, digits, `.`, `_` or `-`. Document IDs are stable
asset identities; node IDs are unique within a document; timeline IDs are unique
within the timeline array. Human names and hierarchy positions are not IDs.
There are no component definitions or component instance overrides yet.

The parser rejects duplicate JSON keys, trailing commas, non-finite numbers,
malformed numeric spellings, invalid UTF-8, unpaired Unicode escapes, raw control
characters inside strings, NUL and extra trailing values. Validation includes
opaque extension/editor data. Source size is limited to 16 MiB; JSON nesting to
128; node hierarchy depth to 48 and node count to 65,536. Diagnostics include
the JSON pointer, zero-based UTF-8 byte offset, one-based line and one-based byte
column. Missing fields use their enclosing/default location until a dedicated
missing-token diagnostic is added.

## Typed values and layout

Every property is a typed object; raw CSS strings are not accepted. Tokens are
named typed values in the root `tokens` object. A property/key can use
`{"type":"token","value":"marine.olive"}`. Token definitions contain concrete
values; alias chains are not supported. An edit to a token revalidates and
resolves every reference in the candidate model.

| Type | Value | Notes |
| --- | --- | --- |
| `number` | Number | Property-specific range, e.g. opacity 0–1 |
| `length` | Number plus explicit `unit` | `dp`, `px`, or layout `%` |
| `color` | `[r,g,b,a]` | Straight sRGB, each channel 0–1 |
| `keyword` | One allowed keyword | Validated for the specific property |
| `font` | Font identifier | Host resolves the font family |
| `text` | `#str_*` localization key | Runtime translates then escapes markup |
| `transform` | `[x,y,sx,sy,degrees]` plus `unit` | Translation uses `dp` or `px`; scales are dimensionless |

The current node types are `group`, `text` and `vector`. Each has an `id`, `type`, optional
`properties`, `children`, `mask`, `control` and `extensions`. Text content belongs only to text
nodes; text nodes cannot own children. The root is a normal node inside a
viewport-filling retained document.

The property registry in `Document.cpp` currently supports:

- Left/right/top/bottom anchors; width/height and their min/max constraints;
  margins, padding, row/column gaps and border widths, including side values.
- Relative/absolute positioning, display, overflow, box sizing, flex direction,
  wrapping, justification, alignment and grow/shrink.
- Font family/size, line height, letter spacing, color, text alignment and
  whitespace policy, plus localized text content.
- Background and border colors, opacity and a composed transform.

`opacity` applies to the node's complete subtree using
[isolated composition](composition.md), including when it is animated. Paint
alpha is separate. Nested group opacities compose inside-out, and subtree paint
ordering stays stable when a temporary layer appears or disappears at opacity 1.
The canonical format remains version 1 during this pre-release schema phase;
this corrects the earlier per-primitive rendering behavior.

Negative anchors, margins and letter spacing are supported; sizes, padding,
gaps and border widths cannot be negative. Percentages are not accepted for
font metrics, borders or transform translations. `auto` is supported for
anchors, dimensions and margins. Additional layout constraints, components,
bindings and material/image nodes remain to be implemented. Native vector nodes
now have a `paths` array; their [source/compiler contract](vector-paths.md)
records supported curves, strokes, paints and remaining quality gates.

Every node type can have an alpha `mask` object with `paths` and optional
`extensions`. These paths use the same schema as vector artwork and their own
path-ID namespace. Coordinates resolve against the node's border box, including
padding. Masks follow its transform and dp scale. Mask paths paint in source
order; their resulting alpha multiplies the completed subtree once. Colors do
not affect mask strength. Fills, strokes, gradients, holes and pixel coverage
all contribute alpha. An absent mask leaves paint unchanged; `{"paths":[]}`
hides the entire subtree. Nested masks and group opacity compose inside-out.
See [vector masks](masks.md) for rendering, tests and limits. Mask values support
the same transactional JSON-pointer edits and source diagnostics as artwork;
mask points/paints are not yet timeline or game-binding targets.

An optional `control` supplies button semantics independently of its vector/text
parts. Its [interaction contract](interaction.md) defines localized labels,
semantic action IDs, enabled state, navigation links and five required state
timelines. Feedback stays within the button subtree, covers the same properties
in every state and preserves the button's own hit box. The runtime uses these
declarations for focus, paired activation and modal input scopes; other widget
roles and game bindings remain open. [Input ownership](input-routing.md) connects
these declarations to SDL and session routing and records its qualification limits.

The render adapter owns the conversion into RmlUi syntax. In particular, RmlUi
RGBA functions use integer 0–255 alpha, whereas this document stores 0–1 alpha.
Conversion rounds channels at the layout backend boundary. Transform functions
are emitted as translate, scale, rotate; the resulting matrix applies rotation,
then scale, then translation around the retained transform origin (center by
default). Source coordinates remain in their authored units across a DPI change.

Document loading does not concatenate translated strings into RML. Text nodes
receive translated, encoded content through the same runtime text path. The
current engine font backend and its limitations are recorded in the
[renderer checkpoint](runtime-spike.md).

## Lossless edits

`Document::Load` builds a candidate model and only replaces the active source
after parsing and semantic validation succeed. An unchanged round trip returns
the original bytes, including line endings, whitespace, comments, member order
and extension data.

`ReplaceValue(jsonPointer, jsonValue, diagnostics)` replaces an existing value
span, using JsonCpp's source offsets, then validates the entire candidate:

```cpp
document.ReplaceValue("/tokens/space.frame/value", "28", diagnostics);
```

All bytes outside that value span remain untouched. Replacement containers can
include comments, which are retained. Leading/trailing comments supplied outside
the replacement value are excluded so a trailing `//` cannot swallow the
containing document's punctuation. Comments inside a deliberately replaced
container belong to that replaced container; callers must carry them forward
when making structural edits. JSON pointer `~0`/`~1` escapes are supported;
array indices must use their canonical decimal spelling.

This API implements transactional value edits and whole-document reloads. It
does not yet implement insertion/deletion/reordering with comment attachment,
undo/redo, atomic filesystem saves, autosave, external conflict resolution or
multi-document editing. Those are editor gates, not inferred capabilities of
retaining the original source string. Direct raw style/text mutation is refused
for a canonical runtime document; editor changes must update its source/model.

## Presentation tracks

Each timeline has `id`, positive `durationMs`, `tracks`, optional `iterations`
(default 1; 0 repeats until cancelled) and optional `essential` (default false).
Each track targets one `node` and `property`, with at least two `keys`. A key has
`atMs`, typed `value` and optional cubic-Bezier `easing:[x1,y1,x2,y2]`. The easing
belongs to the interval beginning at that key. All four coordinates currently
lie in 0–1; overshooting curves are not yet supported.

Key times increase strictly, start at zero and stay within duration. A last key
before duration holds its value through the remaining interval. A target must
exist and have an explicit base property. All key types and units must
interpolate with that base. Layout percentages cannot interpolate with dp/px;
authors must choose one space. Numbers, lengths, colors and transforms animate;
keywords, font names and localization keys are discrete and not accepted in
tracks. Color interpolation uses premultiplied sRGB, then returns straight RGBA
for the backend conversion, preventing transparent endpoints from tinting or
darkening the visible interpolation.

Margin, padding, border-width and border-color shorthands expand into effective
side properties in the resolved model. Explicit side values override the
shorthand regardless of JSON member order. Animated shorthands expand the same
way: a newer left-side transition owns only that side, and cancelling an older
whole-box transition cannot overwrite it. Duplicate effective owners inside one
timeline are rejected.

`Motion` is the first-party evaluator used by `Runtime`:

- Input time is absolute monotonic seconds. The clock never advances backwards
  or accepts non-finite time. A long sampling gap advances by the full elapsed
  time; it does not inherit RmlUi's 100 ms CSS-animation delta clamp.
- `Play` samples current playback at that exact time and uses the current
  property value as the first key of the new transition. The newest explicit
  play owns each property independently. Other tracks continue. Later loop
  iterations return to the authored first key, not the interrupted start.
- `Pause` freezes owned tracks; `Resume` excludes the paused interval.
  `Cancel` either holds the sampled value or restores its authored base. It
  affects only properties the named timeline still owns. Completed tracks hold
  their endpoint and release ownership; cancellation does not reset an already
  completed track or overwrite a newer owner.
- `Scrub` returns pure authored-time samples for one timeline, clamped to its
  first/last presentation time. It does not mutate running playback or dispatch
  actions. Runtime and future timeline editor share this evaluator.
- Reduced motion applies nonessential spatial/color/layout endpoints
  immediately and uses a single opacity transition of at most 80 ms. It removes
  decorative repetition and key oscillation. Enabling it during playback samples
  current opacity before retargeting. Disabling it never resurrects cancelled
  motion. Essential gameplay-information tracks retain their authored timing.

This checkpoint covers property presentation. Action/event markers, game-state
bindings, named legacy script events, state graphs, sound scheduling, layout
invalidation policies, map/unload cancellation and save restoration still need
their semantic bridge. No functional menu behavior is claimed from animation.

## Integration and dependency

`ui_retainedPreview "path.q4ui"` loads through the engine VFS. Syntax/semantic
failures report file, line, column and pointer and keep the previous preview.
`ui_retainedPlay "enter"` starts an authored timeline. The diagnostic CVar
`ui_retainedReducedMotion` can change preference during playback. Preview
documents are recreated after video/font-language generation changes; active
playback is cancelled and explicit replay is needed. These are development
commands, with no host-input capture.

[JsonCpp 1.9.6](https://github.com/open-source-parsers/jsoncpp/tree/1.9.6) is pinned
through Meson under its MIT licensing option. The archive SHA-256 is
`f93b6dd7ce796b13d02c108bc9f79812245a82e577581c4c9aabe57075c90ea2`.
The [upstream notice](../../licenses/JsonCpp.txt) is retained and installed into
`licenses/`. README credits its authors. The three implementation files form a
static dependency isolated from engine headers. Dedicated binaries do not link
the document parser or retained renderer. No new dynamic runtime DLL is added.

The parser supplies a DOM and source offsets; openQ4 supplies schema validation,
source-span transactions and motion evaluation. JsonCpp's permissive handling
of some numeric/string forms is checked by a small lexical preflight before DOM
parsing. The complete source/metadata tree is checked for valid Unicode and
finite numeric values.

Native targets `openq4-ui-document-test` and `openq4-retained-ui-test` exercise
production parser/evaluator/layout code. Coverage includes byte-exact round
trips, scalar/string/container spans, comments and pointer escapes, transactional
failure, duplicate/dangling IDs, tokens, localization requirements, non-finite
and malformed Unicode/numbers, source diagnostics, clipping, density/aspect,
alpha conversion, cubic easing, 250 ms stalls, 240 Hz samples, reversal/ownership,
pause/resume, hold/base cancellation, loops, editor scrubbing and live reduced
motion. These are synthetic sampling checks, not measured game frame rates.

The canonical fixture is
[`document-smoke.q4ui`](../../../tools/ui/fixtures/document-smoke.q4ui). It uses
stock localization keys and diagnostic rectangles; the production vector
component/artwork gate remains open. It is not shipped as runtime content.
Gameplay capture commands and reviewed evidence are recorded alongside the
runtime checkpoint after validation. Neither native tests nor this fixture
qualify the full editor, replacement corpus or other platforms.
