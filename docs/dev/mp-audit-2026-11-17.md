# Multiplayer audit, 17 November 2026

A review of multiplayer as it stood after the rounds of 13 to 15 November
(buying rules, the Classic ruleset, casual match flow, the map database,
modifiers and presets, client options, spectating, the netcode audit and
protocol 2.42): what was found, what this round changed and what is still
open. It feeds MP-08, MP-10 to MP-16, MP-18 and MP-23 in the
[roadmap](roadmap.md). The network items follow the
[14 November netcode audit](mp-network-qualification.md#netcode-audit-14-november-2026).

## How it was done

- Six read-only reviews, each told what earlier rounds had already fixed:
  match flow and votes; rulesets, the map database, presets and buying; client
  options, chat, spectating and the event stream; per-frame cost; the engine's
  network layer; and gameplay (weapons, items, powerups).
- Every finding was read again against the code before anything was changed.
  Findings that depend on a decision, need a new network format, or could not
  be checked in play were left open and are listed as such.
- The unchanged tree was measured first: 125 static multiplayer tests and a
  six-bot match on `mp/q4dm1`. Two tests already failed there (stale fixtures,
  repaired below), and the match's log showed player models and damage
  definitions being read from disk in the middle of play.

## Findings and what was done

### Match flow, votes and pauses

| Finding | State | What was done |
|---|---|---|
| `g_inactivity` dropped an idle player from inside that player's own `Think`. Dropping a client deletes its player at once, so the rest of the think and the frame's think loop ran on freed memory. | **Fixed** | The drop is queued for the occupant of the slot and runs from `idMultiplayerGame::Run` (`QueueClientDrop`, `RunQueuedClientDrops`). |
| A casual server imported its limits into the match rules once and mirrored them back at every map start. A limit changed by a passed vote, at the console or by hosting again with other settings was put back at the next map or restart; a `buying` vote did nothing at all. | **Fixed** | `InitializeCompetitiveRules` lays the server's settings over the rules in force at every map start and restart and commits them when they differ. Rules set by a typed operation that no setting carries are kept. Settings that are not valid rules are refused with a warning and the rules in force stay. |
| The same import ran on a joining client and wrote the server's limits over the player's own archived `si_` settings, and a stale copy over the server info the client had just been sent. | **Fixed** | A client keeps a local snapshot and mirrors nothing. |
| The vote electorate left out everyone flagged `spectating`: an eliminated player, everyone on the end-of-match scoreboard, players benched by sudden death. Nobody could call a vote on the scoreboard, and a lone survivor passed any vote alone. | **Fixed** | A spectator is someone who chose to watch (`wantSpectate`). The retained Vote page asks the same question and honours `si_spectatorVote`. |
| `si_spectatorLock` asked only about spectators coming back, so a client connecting with `ui_autoJoin 1` walked into a live match or a sudden death. A locked-out spectator had only to reconnect. | **Fixed** | Someone whose first join is being decided is held like a returning spectator and told why. Bots still fill by their own rules. |
| With the lock on, the player `g_pauseOnDisconnect` waited for was refused when they came back, and the side forfeited when the pause ran out. | **Fixed** | The side a disconnect pause is held for may take a player in. |
| `g_pauseOnDisconnect` had no budget, fired for kicks and idle drops, and ran its full length after the player had returned. Nobody but a referee can end a technical pause, so one player could hold a match still by leaving and rejoining. | **Fixed** | One pause a side a match; a client the server removed itself does not pause the match; the pause ends once the side has a player more than it was left with. |
| The stock vote menu's message skipped `g_voteLimit`, and its next-map vote was gated on the map vote's switch instead of its own. | **Fixed** | Both transports apply the same limits and switches. |
| The mirror wrote `si_overtime 0` whenever a map ran without a time limit, which lost the operator's value for good. | **Fixed** | With no time limit the setting is left alone. |

Still as it was: an `overtime` or `timelimit` vote during a live match changes the
running match only where the game reads the setting directly; the match
session keeps its regulation deadline and overtime policy until the next
start. A vote that is refused because voting is off or the field is forbidden
is refused silently. Console replies such as `ready:` are English.

### Rulesets, the map database, presets and buying

| Finding | State | What was done |
|---|---|---|
| Changing `si_ruleset` on a running map (a passed ruleset vote, `preset classic`, the console) hung the server: the change queued a restart, the restart saw no changed key because the server info already held the new value, restarted in place, rescanned and queued another. | **Fixed** | The change asks for one full load through the session command, and `MapRestart` treats a ruleset that differs from the one the map was loaded with as a reason for a full load. |
| `preset` with a game type the running map cannot play said "applied"; the restart was refused as incompatible and its latch stayed set, so later modifier changes never restarted the match and the server info advertised rules the server was not running. | **Fixed** | A preset whose game type no installed map plays is refused before anything is written; otherwise the server moves to a map that plays it, as a passed game type vote does. A refused restart clears its latch. |
| The rotation chose the next map for the game type being played, not the one set for the next map. The load then refused the map as incompatible until the request was thrown away. | **Fixed** | The rotation, the prediction and the end-of-match pick use the pending `si_gameType`. |
| A player who had joined a server or played back a demo and then hosted got no `mapdb.txt` on the first map, and a rotation built from the server they had left. | **Fixed** | The map host knows it is preparing a map to serve (`ClientRole`). |
| Map votes asked the mapDef what a map plays, not the map database: a `modes` override was ignored in both directions. | **Fixed** | Both checks ask the database. |
| The shuffle's "recently played" window was half of every installed map, so a short `si_mapCycle` called all of its maps recent and alternated between two. | **Fixed** | The window is half of the rotation. |
| One queued map could be taken twice when the server ran several game frames before the map change. | **Fixed** | The repeat window is 32 frames instead of 4. |
| A map's own `set` values stayed in the configuration file after `quit` on that map, and the next launch read them as the operator's own. | **Fixed** | A quit stops the server and writes the configuration while it still can. A crash on such a map still leaves them. |
| A UTF-8 byte order mark made `mapdb.txt` and preset files fail on line 1. | **Fixed** | Both readers skip it. |
| The database publishes `si_nextMap` and `si_mapPick` with a full `rescanSI`, which also latches any other `si_` setting typed for "next map". | Open | Needs an engine command that publishes named keys only. |
| `ServerAdvance` is not gated for managed matches the way the queue and the pick are. | Open | Whether a managed match reaches it was not traced. |
| Classic with buying: an armour purchase at 100 combat armour costs credits for nothing, and bots do not route to Classic armour (`inv_armor_tier`). | Open | Narrow; left for MP-10 and MP-11. |

### Client options, chat and spectating

| Finding | State | What was done |
|---|---|---|
| An eliminated team member was treated as a neutral spectator: the server sent them every living opponent's position, health and armour, the Competitive layout listed both teams with locations, and outlines drew opponents through the world, while their team chat still reached the team mates playing on. | **Fixed** | Only someone who chose to watch gets the all-players snapshot, the both-teams list and the spectator outlines. A participant in a spectator camera keeps their own side's view. |
| A participant in a spectator camera (eliminated, between Tourney fights, benched by sudden death) could follow nobody and sat in free flight. | **Fixed** | They ask to follow as a spectator: a sided one gets their own side and no other. |
| Cycling with nobody to follow moved a free camera to a spawn point: alone on a server every attack press was a teleport. | **Fixed** | A camera that is already free stays where it is. |
| Item timers survived the restart in place at a match's start and at each round: a quad taken in warmup went on counting down through the first minute of the match. | **Fixed** | The restart clears the restarted instance's timers. |
| `buy` and `emote` were sent through the path that drops events outside a new frame, so from a bind or a menu button they were lost at random on a remote client. | **Fixed** | Both use the request path `follow` got on 15 November. |
| Team chat cut eliminated players out, their own lines included, and spectator-only chat reached them. | **Fixed** | A team line goes to the whole team; a spectators-only line to those who chose to watch. |
| A player named `server` spoke as the server. | **Fixed** | The name is taken, with or without colour codes. |
| A `say` longer than the chat message could hold was a fatal error on the client. | **Fixed** | The line is cut to what the server reads, on a character. |
| `say_team` with tokens outside a team game went to everyone with the tokens expanded. | **Fixed** | A team line that will go to everyone keeps its tokens as typed. |
| The chase and death cameras start their clip trace from a raised point that is not itself clipped, so under a low ceiling the camera can sit in solid. | Open | Needs a by-eye pass. |

Still as it was: the local clock's `AM`/`PM` and the chat suffixes are English;
the event stream is closed on map load and shutdown, not on disconnect.

### Gameplay

| Finding | State | What was done |
|---|---|---|
| The drop-weapon message, which no client offers, was obeyed from a modified one: each message left a weapon item with a full starting load of ammunition, a refill for the sender and enough items to run the map out of entities. | **Fixed** | The server ignores it. A weapon is still dropped when its carrier dies. |
| The Chain Lightning Mod never chained for Marines or in a non-team game, and a Strogg's beam could arc to its owner or team mates: the search walked single-player team lists. | **Fixed** | In multiplayer the search walks the players: opponents in play in the owner's instance. |
| The Ammo Regen rune turned a weapon arena's unlimited ammunition into none. | **Fixed** | Unlimited ammunition is left alone. |
| FC Armor Regen ended with about twenty armour gone in a third of a second. | **Fixed** | Its clock runs for the whole powerup. |
| The Bounce Shot and Burst Fire mods fire projectiles a remote client cannot follow: their definitions are single-player ones with no physics sync, so every client draws the bolt or rocket flying straight to an impact that did not happen. | Open | The fix makes those projectiles physics-synced on both ends; it needs a remote-client capture of each mod to accept. Recorded under MP-10. |

Inherited from the SDK and left for a decision: DeadZone's zone list holds raw
player pointers across a frame; `teleportKiller` is a bare entity number held
across a delayed teleport; the nailgun seeker filters on the local player's
team (its mod is not sold).

### Engine network layer

| Finding | State | What was done |
|---|---|---|
| The 2.42 packet tag was written as a signed short, so every tag with its top bit set logged a value-overflow warning: about thirty lines a second on a client. The bytes on the wire were right. | **Fixed** | Written and read as an unsigned short; the bytes are the same. |
| An out-of-band `print` carrying the server's address still ended an in-game session: a bad-challenge notice made the client reconnect, a denial disconnected it or opened a password prompt over the match. A late duplicate of an accepted `connect` did the same with no attacker. | **Fixed** | Both are obeyed only during the handshake that draws them, and printed otherwise. |
| An `auth` packet from anyone printed a console and log line each, and so did a runt channel packet, before the tag check. | **Fixed** | Developer prints. |
| An rcon lockout is a server time, and the server clock restarts with the map: five wrong passwords late in a long map locked that address out for the length of the map, not thirty seconds. | **Fixed** | What is left of a lockout is carried over the map change. |
| A master server lookup that failed once was reported as a success from the second call on, so a server started before its name service was up sent heartbeats to nowhere until restart. | **Fixed** | A failed lookup stays failed and is tried again at each forced heartbeat (map start, the `heartbeat` command). |
| A datagram larger than the receive buffer ended the frame's packet drain, so one or two a frame held every client's commands back. | **Fixed** | Read past, a bounded number of times, on Windows and POSIX. |
| The global challenge budget also drops a `connect` that has already proved its challenge, and per-source limits key on a whole IPv6 address. | Open | The budget is a deliberate reflection control; how far to loosen it is a decision. |
| An attacker can have their rcon limiter entry evicted between challenge and proof, so failures are never counted. | Open | Needs entries with failures made unevictable; matters for weak passwords only. |
| A joining client is queued every other client's whole user info in one frame; a server full of clients at the user info limit overflows the joiner's reliable queue. | Open | Needs the join burst staged over frames. |
| A connected client's malformed packet logs a line a packet and is never dropped. | Open | |
| MVD snapshots are paced in milliseconds against the 16 ms game clock: 15 a second where the default asks for 20. | Open | Fixing it makes recordings about a third larger; a storage decision for MP-23. |
| A name containing byte 0xFF ends its own user info string early. | Open | |

### Per-frame cost

| Finding | State | What was done |
|---|---|---|
| A bot traces up to seven sight lines to every enemy in range and in its view cone, every tic, and tries all seven on each one that is behind the map. | Not changed | Asking the map's visibility data first was built and measured: it saved nothing (below), so it was taken out again. |
| Player models, heads, skins and the multiplayer damage definitions were read from disk mid-match: the spawn precache asked for the single-player names of definitions multiplayer redirects to `_mp`, and a player or bot arriving with a model nobody had used yet loaded it on the server and on every client that could see them. | **Fixed** | The `_mp` definitions are cached, and every player model is loaded with a multiplayer map (`g_precachePlayerModels`, on by default). Measured below. |
| A listen server wrote its host's decaying DeadZone score-bar pulses into every snapshot; no client reads them. | **Fixed** | The fields stay and stay zero. |
| `pm_isZoomed`, the process's look-sensitivity scale, was written by every player's `Think`: on a listen server the host's mouse slowed whenever the player who thought last was scoped. | **Fixed** | Only the local player writes it. |
| A client redoes presentation work for every remote player on every replayed tic (view-model animation twice, visibility effects). | Open | About 0.3 to 0.5 ms on a frame that follows a snapshot with fifteen remote players, by estimate; the gates sit under MP-07's qualified weapon presentation and need its captures re-run. |
| Each client's snapshot tests every spawned entity against the PVS, networked or not. | Open | 0.06 to 0.3 ms a tic at sixteen clients, by estimate; measure first. |
| `FindEntityDef` formats a name and looks up twice in multiplayer; bots call it about nine times a tic in combat. | Open | Small. |
| Item timers rebuild their list from every entity slot three times a recipient. | Open | Once a second, spectators only at the default policy. |
| Resting items re-present and drop their PVS-area cache every tic; `UpdateHud` republishes its base keys every draw frame; the corpse sink runs on every prediction pass. | Open | Each small; listed for a later pass. |

## Measured

All on the reference machine in a hidden 960x540 OpenGL window, a listen
server on `mp/q4dm1` or `mp/q4dm8` with bots, while another session ran its
own clients, so the figures compare configurations of one build and are not
budgets.

- **Loads in the middle of a match.** A six-bot match on `mp/q4dm1` logged 53
  "non pre-cached" loads after the map had started (player models, heads,
  skins, their materials, and the fall damage definitions). With the `_mp`
  definitions cached and `g_precachePlayerModels 1` it logs none. The map
  load took 4,279 ms with the model precache off and 3,900 ms with it on, back
  to back: no cost that shows above the run-to-run difference.
- **Bot sight.** Eleven bots on `mp/q4dm8`, `bot_profile 10`, the visibility
  check switched on, off and on again inside one match: average bot think time
  was 1.85, 1.91 and 2.16 ms with it on, 1.39, 2.01, 1.65 and 2.04 ms with it
  off, then 2.03, 2.38, 2.14 and 1.67 ms with it on again. No saving; the
  check was removed. The seven-trace search is still there for a later pass
  that can count traces rather than time them.

## Checked

- **Static tests.** The 125 multiplayer, network and demo tests of
  `commit-validation.yml` that need no game pass. Two failed before this round
  on the unchanged tree and are repaired: `mp_match_flag_map_contract.py` (its
  stand-in lacked `PickupInhibited`) and `ui_player_targets.py` (byte offsets
  from before the packed vote's flag word became a long). Eight were updated
  for behaviour this round changed on purpose.
- **A limit changed on a running server.** Launched with `si_fragLimit 999`;
  `set si_fragLimit 33` and `serverMapRestart` left it at 33 (the old import
  put 999 back).
- **A ruleset change on a running map.** `set si_ruleset 1` and `rescanSI`
  during a live match loaded the map again once; the match went live under
  Classic and ran on. The old code never returned from that command.
- **An idle remote client.** Listen server with `si_spectators 0` and
  `g_inactivity 12`, one remote client that sends no input: the server printed
  "Dropped for inactivity", ran on and quit cleanly.
- **A joining client's own settings.** The same client was started with
  `si_fragLimit 41` and `si_timeLimit 7` and joined a server running 17 and 0:
  its own values were unchanged at the end.
- **Casual match flow.** `mp_casual_flow_smoke.py` on the final build
  (OpenGL, Team DM on `mp/q4dm1`): all eleven checkpoints pass: the coin-toss vote, both
  team timeouts and the refused third, the round-limit vote, the spectator
  lock and the idle move to spectators.

Not run: the spectator, client-options, map-rotation and modifier smokes on
the final build; Vulkan; a dedicated server; real input; and any play by
people. The spectating, chat, electorate, disconnect-pause, map-rotation,
preset and gameplay fixes are covered by their contracts and by reading, not
by a run that exercises each one.
